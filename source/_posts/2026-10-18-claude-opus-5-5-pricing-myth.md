我最初是喜欢 Opus 5.5 的。模型更强，价格又降了，这当然值得高兴。我同时订阅着 Claude Pro 和 ChatGPT Plus，也实际使用 Claude Code 和 Codex，有理由期待竞争最后能给用户带来实惠。

但看完自己的消耗记录、AA 的测试，再把罗福莉谈推理降本的帖文与 Anthropic 的扩容、故障记录放在一起，我越来越不愿意照单全收“更强又更便宜”这个故事。

我现在更倾向于把它看作 IPO 窗口前的一场价格竞争：一边用降价争夺用户、展示增长，一边仍要处理昂贵的算力供给和服务交付问题。这是我的判断，不是我掌握了 Anthropic 的内部决策文件。我要追问的是，降价背后的工程账交代了多少，投资者喜欢的增长又有多少会兑现成用户的好处。

<!-- more -->

## “便宜 40%”到底在和谁比？

Anthropic 在 2026 年 9 月 22 日的发布说明中，将 Opus 5.5 描述为能力提升、运行费用下降的新模型。它所说的“典型工作负载下降 40%”，对照对象是 **Opus 5**，条件是其测试中的默认设置；这不等于比所有竞争模型便宜 40%。[发布原文](https://www.anthropic.com/claude-opus-5-5)

官方文档确认，每百万 Token 的普通输入价从 5 美元降到 4 美元，输出从 25 美元降到 20 美元，分别下降 20%；缓存读取从 0.50 美元降到 0.20 美元，下降 60%。Opus 5.5 的五分钟缓存写入为 5 美元，一小时写入为 8 美元。[定价与迁移文档](https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5)

所以，40% 不是一张价格表上可以直接读出的统一折扣。它混合了不同 Token 类别的降价和特定任务下的消耗变化。换一个缓存比例，换一个推理档位，换一种任务，这个百分比就可能变化。

官方原文写出了对照对象和测试条件；我批评的是这套产品叙事的吸引力：上一代是价格基准，优势任务是能力基准，两者合在一起，“更强又更便宜”就成了一个很容易接受的购买理由。可它仍没替我回答，在今天的其他选择面前，Opus 5.5 是否值得这个价。

## 我的统计里，最容易被忽略的是缓存

我买的是 Claude Pro 和 ChatGPT Plus。以下 CC Switch 金额均为 API 等效费用，用来观察消耗结构，不是额外支付的账单。

最近 30 天，Claude Code 下的 claude-opus-5-5 有 1264 次请求，约 360M Token，等效费用 118.58 美元；Codex 混合多个 GPT 模型，有 4612 次请求，约 623M Token，等效费用 168.75 美元。原先盯着总量，我会觉得 Codex 用得多得多。按请求数一除，画面又变了。

我的日常设置也要交代：Opus 5.5 主要用 Medium，偶尔 High；GPT-6.1 Sol 主要用 High，部分时候 Medium。Codex 的总数还包含其他 GPT 模型，不能把整张统计表当作 GPT-6.1 Sol 单模型的表现。不同厂商的同名推理档位，也不代表相同计算预算。

![Claude 的 CC Switch 最近 30 天统计](https://files.seeusercontent.com/2026/10/17/t6Aa/pasted-image-1792256435566.webp)

![Codex 的 CC Switch 最近 30 天统计](https://files.seeusercontent.com/2026/10/17/b5Os/pasted-image-1792256422914.webp)

Claude 平均每请求约 0.0938 美元，Codex 约 0.0366 美元，前者约为后者的 2.56 倍。平均总 Token 分别约 28.48 万和 13.51 万，比例约 2.11 倍。

![平均每请求 API 等效成本](https://files.seeusercontent.com/2026/10/17/tAr9/pasted-image-1792257149897.webp)

但请求不是任务。一次工具调用可能产生请求，一项工作可能拆成很多请求；Claude Code 和 Codex 的工具编排、上下文管理并不相同，后者还混用了多个模型。这组数字描述了我的两套使用组合，不能被改写成“Claude 完成相同任务贵 2.56 倍”。

这组个人记录没有统一任务、验收结果和返工时间，却清楚显示了我的使用组合如何消耗资源。它给了我继续追问的理由。消费者也有权从自己的工作出发理解产品，而不必永远停留在厂商挑选的成功案例里。

## 命中缓存 98.8%，为什么还有这么多费用？

Claude 的统计显示，缓存命中率为 98.8%，其中缓存读取约 355M、写入约 4.46M，输出约 1.27M。新增普通输入只显示 2682 Token，异常原因尚未确认。

按已核实的价格、并将写入统一按五分钟档位估算：缓存读取约 71 美元，输出 25.40 美元，缓存写入 22.30 美元，普通输入约 0.01 美元，合计约 118.71 美元。它与软件显示的 118.58 美元相差约 0.13 美元。汇总值舍入可能造成差异，写入时长等细节也需要日志确认。

![Claude 等效成本构成，按五分钟缓存写入费率重算](https://files.seeusercontent.com/2026/10/17/v9Xp/pasted-image-1792257170784.webp)

355M 缓存读取约占显示总 Token 的 98.6%，却仍占重算费用的约 59.8%。前一个比例是我用汇总量相除得到的数，和软件显示的 98.8% 命中率不能混为一谈。

缓存命中意味着复用已经处理过的内容，通常省去了重复处理的一部分开销。它有折扣，也仍然计费。缓存单价很低，乘上足够大的复用量，就可以成为主要费用来源。

再把这组用量固定，按 Opus 5 的旧费率重算，费用约为 237.14 美元；按 Opus 5.5 费率则约为 118.71 美元，差不多减半。其中单是缓存读取降价，就节省约 106.50 美元，占这次费率重算总节省的约九成。

这笔账说明，对我这种缓存占比极高的组合，降价确实有分量。它也把“降价”的结构说清了：大部分节省来自反复读取上下文的折扣。这里固定了 Token 用量，未测量两代模型完成同一任务的消耗变化；我的记录因此既不能验证，也不能推翻官方典型负载的 40% 说法。降价兑现到哪一步、与竞品相比还有多贵，是接下来要分开回答的问题。

我在两套工具里看到的差异，也集中在这里：Claude 平均每请求读取约 28.09 万缓存 Token，Codex 约 13.01 万；输出分别约 1005 和 449 Token。重复携带的上下文比最终输出大得多。对 Agent 的费用讨论，如果只盯着“回答写了多少字”，会漏掉大量被反复读取的历史内容。

![平均每请求缓存读取与输出 Token，分面显示](https://files.seeusercontent.com/2026/10/17/1oSu/pasted-image-1792257192011.webp)

高缓存命中率无法单独证明整套工作流程高效。哪些历史必须保留，哪些调用值得发生，最终产出了多少可验收成果，决定了这些费用花得值不值。

而对订阅用户，API 等效费用和套餐额度之间也没有一张已经公开、可供我逐项复算的固定换算表。不能拿这 118.58 美元直接推断我会多快触顶。我想知道的是，同样一档订阅，能否稳定做完更多工作，是否需要中断等待或加购额度。这次记录没有覆盖这些结果，所以它提供的是追查线索，还不是一场订阅性价比实验。

## AA 的领先，也带着成本标签

Artificial Analysis 的页面给出了另一种观察。截至 10 月 18 日检索时，Opus 5.5 的“max with fallback”配置，智能指数为 58、每项智能指数任务成本为 5.98 美元；GPT-6 Astra 的 max 配置为 53、3.26 美元。前者得分更高，成本也约为后者的 1.83 倍。[Opus 页面](https://artificialanalysis.ai/models/claude-opus-5-5)、[Astra 页面](https://artificialanalysis.ai/models/gpt-6-astra)

在这两项配置之间，Opus 得分领先，测试费用也更高。能力增益值不值差价，要看它解决了什么问题。指数 58 对 53 也不是生产率提高了约 9%，拿分数相除并不能得到我的工作收益。

AA 测试的是 Max 配置，与我的日常档位不同；Opus 这一行还带有 fallback。这些条件应当跟着数字一起被看见。

AA 方法页说明，智能指数优先使用厂商 API 报告的 Token 数来计算费用；这与速度测试使用统一 tokenizer 的方式不同。成本也采用基准权重和缓存测量，不能把所有标签里的“max”当作相同的计算预算。[AA 方法说明](https://artificialanalysis.ai/methodology/intelligence-benchmarking)

AA 的输出 Token 图把这层代价展示得更直观：Opus 5.5 Max with fallback 每任务加权平均总输出约 119K，其中推理约 84K；GPT-6 Astra Max 的总输出标注约 27K，GPT-6 Sol Max 约 38K。119K 已经包含推理部分，不能再加一次 84K。

![Artificial Analysis 每任务输出 Token 截图；总输出含推理部分](https://files.seeusercontent.com/2026/10/17/hD3q/Output-Tokens-per-Intelligence-I.png)

按截图标注总量，Opus 约为 Astra 的 4.4 倍、Sol 的 3.1 倍。截图中的分项与总数存在小幅不一致，可能涉及各自取整，不宜根据这些显示值反推精确原始数；截图也没有显示采集时间和指数版本，不宜与实时页面拼成一张精确的历史实验记录。

这些倍数衡量的是图中的计费 Token 消耗，并非算力或浪费程度。但当较低单价被当作优势时，更多的消耗同样应当进入讨论。多花的 Token 换来了哪些必须依靠它才能完成的成果？如果这部分收益没有进入我的任务，榜单上的领先就不能抵扣我的使用成本。

还要正视一组与上述结果方向不同的材料：Anthropic 在同一发布页中，声称 Opus 5.5 默认 Medium 档位在 FrontierCode 上，以约五分之一的任务费用超过 GPT-6 Astra 的最高分。这与 AA 的 Max 综合指数不是同一场测试：基准、推理档位和工作流程都不同。它说明成本优势可能随任务和设置而反转，也说明只摘出一张有利图表，就可以讲出很不一样的产品故事。我希望看到的是自己的典型工作落在哪一边。

## 罗福莉这段话，让我更想追问 Anthropic 的工程账

罗福莉关于 MiMo API 降价的帖文，是我不想漏掉的一块材料。下面的 X 中文译文截图与对应英文存档内容相符：她把最大幅度、最高 99% 的降价放在缓存命中输入上，称推理框架的分层 KV 缓存优化使缓存容量提升约五倍，相当于缓存成本下降约 80%。她还提到原先约 2–3 倍的利润空间，以及新价格下在接近满负荷运行时基本收支平衡的判断。[英文存档](https://ww.twstalker.com/_LuoFuli/status/2059618247553745204)、[原帖地址](https://x.com/_LuoFuli/status/2059618247553745204)

![罗福莉关于 MiMo API 降价的 X 中文译文截图，界面标注翻译自英语](https://files.seeusercontent.com/2026/10/17/jo8X/pasted-image-1792256748914.webp)

这段话的价值，在于把降价放回了工程和商业的关系里：缓存如何变便宜，原先定价留了多少空间，为什么现在愿意让出来。这些数字仍是团队负责人的自述，不是审计结论，但至少给出了可以追问的机制。

小米技术文章进一步解释，Hybrid SWA 可将 KVCache 存储降至全注意力结构的约 1/7；缓存管理、前缀匹配和调度需要一起改，才能兑现架构收益。DeepSeek 更早的 V3/R1 系统说明也公开讨论了预填充与解码分离、专家并行及负载均衡。局部收益不等于整套服务成本，但讨论有了具体对象。[小米技术原文](https://mimo.xiaomi.com/zh/blog/mimo-v2-5-inference)、[DeepSeek 系统说明](https://github.com/deepseek-ai/open-infra-index/blob/main/202502OpenSourceWeek/day_6_one_more_thing_deepseekV3R1_inference_system_overview.md)

回头看 Anthropic，缓存读取报价降低 60%，并不是 KVCache 的资源成本也下降 60% 的证据。我查到的 Opus 5.5 发布和迁移说明，给出了更低服务计算需求的结论，却没有给出足以让我复核缓存单位成本变化的前后工程账。缺少这份账，不能断言它毫无优化；同样也不能把售价下降直接当成工程突破的证明。

所以我引入罗福莉，并不是想给另一家公司做广告。我想问 Anthropic：这次降价，有多少来自已实现的工程降本，又有多少来自利润空间的重新分配和抢占市场的需要？后者也是正常商业行为，但消费者不必自动把它当成技术红利，更不必为一张新价目表献上信任。

## 算力可以向马斯克买，稳定交付不能靠发布会代替

所谓“向马斯克借算力”，准确说是算力采购合作。Anthropic 在 5 月 6 日宣布使用 SpaceX Colossus 1 的全部计算容量，称将获得超过 300 兆瓦、22 万块以上 NVIDIA GPU 的新增容量，并把扩容直接与 Claude 用户额度提升联系起来。合作方也发布了相应公告。[Anthropic 公告](https://www.anthropic.com/news/higher-limits-spacex)、[合作方公告](https://x.ai/news/anthropic-compute-partnership)

采购外部算力本身谈不上丢人。但这说明，服务能给用户多少容量，仍与外部供给密切相关。把计算资源买进来，和把每单位资源用得更有效，是两笔不同的账。扩容公告不能替代效率证明。

我对 Anthropic 服务工程能力的评价，也没有对它的模型能力那么高。按官方状态页的 UTC 日期，9 月 29 日出现过同时影响网页、Claude Code、Cowork 和 API 的错误率上升；10 月 6 日 Opus 5.5 再次发生错误率上升；10 月 7 日，又有部分组织被错误判定达到消费上限，导致 API 等产品拒绝请求。这些都是需要用户承受的交付问题。[9 月 29 日记录](https://status.claude.com/incidents/4xvtc2gnq73l)、[10 月 6 日记录](https://status.claude.com/incidents/ch27pb90bn85)、[10 月 7 日记录](https://status.claude.com/incidents/vmys9qn874h4)

![Claude 官方状态页过去 90 天快照：API 标注 99.59% 可用率，截图当下为 Operational](https://files.seeusercontent.com/2026/10/17/z1dY/pasted-image-1792257963326.webp)

这张官方状态页快照也保留了多个产品的异常记录，API 标注的过去 90 天可用率为 99.59%。它不是整个行业的横向排名，更不能证明每次故障都由缺算力造成；控制台报表故障也不该一律算成推理 API 停摆。可这些交付记录，已经足以让我拒绝仅凭模型得分，就给整家公司的工程能力打高分。[官方状态页](https://status.claude.com/)

模型能在测试中解出难题，和付费服务能稳定接住需求，是两种能力。对一家公司而言，前者值得宣传，后者同样应该接受挑剔。便宜一点的 Token，补不回一项工作被错误和中断打散后耗掉的时间。

## IPO 前的降价，我更愿意按价格战理解

这也是我对“更强又更便宜”保持警惕的商业背景。路透社根据看到的招股材料报道，Anthropic 2025 年收入近 46 亿美元，经营亏损超过 80 亿美元，并承担巨额算力投入承诺；报道还把 Opus 5.5 的推出放在对抗 GPT-6 Astra 的竞争和预期 IPO 之前讨论。[路透社报道](https://www.marketscreener.com/news/anthropic-s-ipo-prospectus-shows-sweeping-ai-vision-surging-costs-ce785addd98afe2c)

到 10 月，路透社又援引投资者活动参与者称，公司第三季度收入达到 168 亿美元，并向投资者表示当季在调整后口径下盈利。旧年度亏损、调整后盈利和未来投入，应当分开读。[10 月 14 日报道](https://uk.marketscreener.com/news/anthropic-s-q3-revenue-surges-45-to-nearly-17-billion-ce785dd2d08cf221)

放在这个时间窗口里，我更愿意把降价理解为争夺市场和维护增长预期的商业动作。更低的价格有机会带来更多调用和客户，也让“需求强劲、规模扩大、效率改善”这个故事更容易讲给投资者听。它不需要先被证明是一场全面的底层工程突破，商业上也有充分理由发生。

这正是我想指责的地方：用户为什么要替企业把价格竞争自动解释成技术胜利，再把尚未兑现的规模效应提前当成自己的实惠？我没有证据认定 Anthropic 在亏本倾销或故意欺骗，也没有证据证明未来一定砍额度；但我完全可以拒绝用这样的增长叙事替它的服务和价格背书。

Opus 5.5 的单价确实降了，我这组用量按新费率也确实便宜了。问题在于，降价的参照物是它自己的旧价格；面对竞品的 Token 消耗、用户的任务成本，以及真实的交付稳定性，账远没算完。

我仍然承认 Claude 的模型能力，也仍愿意为真正好用的产品付钱。但面对这次降价，我想说的是：先别急着把它理解成用户赢了。公司需要一场价格竞争，也需要一个好卖的 IPO 故事；我需要的是能稳定做完工作的工具。两者的利益，没理由被默认成一回事。
