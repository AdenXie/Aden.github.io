With just 8GB of video memory, you can deploy a 30 tk/s multimodal AI in your laptop.

My Laptop is a very ordinary gaming Laptop: a Ryzen 7 8845H, 16GB of RAM, an RTX 4060 Laptop, and only 8GB of video memory. According to many people's impression, this configuration can only be used to "play around" with local large models.

But now, when I double-click a startup file every day, the browser opens a chat page: I can view images, watch videos, switch the depth of my thinking, and call native tools. My text generation speed is approximately... 31 tokens/sThe entire process involves no internet connection and no API fees. The one running inside is Qwen3.5-9BThe reasoning framework is llama.cpp。

This article is divided into three parts: How I chose the framework and model; An installation tutorial for beginners, written for every command; And the pitfalls I've encountered and the corresponding solutions.

First, let's talk about the conclusion: What ultimately gets started?

Two points to clarify. First, the "30 tk/s" in the title comes from that test in plain text mode; In multimodal mode, the 34.6 generated only 5 word elements, which is too short and only means that "the speed is on the same order of magnitude" and cannot be considered a formal result. Second,nvidia-smi It shows the usage of the entire graphics card, including the desktop and browser, and is not equivalent to the model's exclusive memory.

Why llama.cpp

There are many tools for running large models locally, but the one I ended up using was... llama.cppWhat I valued were these points:

  • There is no need to compile or install a Python environment. The official release page directly provides a pre-compiled compressed package for Windows + CUDA, which can be extracted and used. I didn't install the CUDA Toolkit or compile any C++ code throughout the process.
  • A program gets things done. llama-server.exe Once launched, it provides both a web chat interface and an OpenAI-compatible API, allowing other clients to connect directly.
  • The GGUF quantization model was used. After quantizing the 9B model to Q4_K_M, it is less than 6 GiB, and 8GB is enough to store it.
  • All the parameters are clearly displayed. The length of the context, the number of layers placed in the graphics card, and the precision of the cache are all command-line parameters, so you know which one to adjust when there is not enough graphics memory.

The price is that it doesn't "click" like some graphical tools, requiring you to type several commands. That's why I wrote this tutorial.

Why was Qwen3.5-9B ultimately chosen?

I didn't choose the right one from the beginning; I changed it three times in between:

  1. The first one downloaded was Qwen3-8B. Halfway through the download I changed my mind and stopped the download; it never started running from beginning to end.
  2. The first one to actually run was Google's Gemma 4 E4B.(Official QAT Q4_0 quantified version). It's fast, with 51–54 tokens/s on my machine, only about 5.2GB of video memory, and it has multimodal and can even enable 8K contexts.
  3. Finally, it was replaced with Qwen3.5-9B. The speed dropped to around 31 tokens/s, and the video memory was tighter, but I wanted the one with stronger overall capabilities.

Before switching, I compared several models that could be considered with 8GB of video memory: Qwen3.5-4B, Gemma 4 E4B, Qwen3.5-9B, Gemma 4 12B, and gpt-oss-20b. To be honest, only the speed of the Gemma 4 E4B in that comparison chart was tested by me. The speed of other models was estimated based on hardware, and the capability score was also a reference value obtained by combining various publicly available benchmarks. The test conditions are not uniform. It helped me make trade-offs, but it wasn't a rigorous ranking.

There are three things to keep in mind when reading these numbers:

  • This is Qwen's official resultsIt tests a model with complete accuracy. I'm running the Q4_K_M quantitative version locally, and the context is only 4096, which will reduce actual performance. I didn't retest these benchmarks on my own machine.
  • It is not a comprehensive lead. In programming tests (LiveCodeBench, OJBench), the 9B is significantly inferior to the GPT-OSS-120B, which is clearly visible in the table.
  • For me, the key points are two other things: a 9B model can match or even surpass the previous generation 30B model in terms of knowledge, instruction compliance, and long text; Moreover, it natively supports viewing images and videos, eliminating the need to find a separate visual model.

To sum up my trade-offs in one sentence:The Gemma 4 E4B is faster and more memory-efficient, while the Qwen3.5-9B is more comprehensive. If you care more about speed, or if you only have 6GB of video memory, the former is a good choice; The following steps in this article also apply to replacing the model file.

Before you start: What you need to prepare

  • One Windows 64-bit Computer, with NVIDIA graphics card, around 8GB of video memoryAnd the graphics card driver has been installed.
  • about 8GB of free hard disk space(Program approx. 0.6GB, model approx. 6.6GB).
  • Networks with access to GitHub and Hugging Face. The model file is over 6GB, so be patient if your internet speed is slow.

All commands in this article are in PowerShell It runs inside. How to open: Press Win Keys, input powershellPress Enter. Simply copy the entire command and press Enter. Anti-quotation marks at the end of a command ` This indicates that "this line is not over yet," and pasting the entire paragraph together will prevent errors.

All files will be placed in the "Documents" folder. llama.cpp In the directory, the command will automatically find your own "document" path, without having to manually change the username.

Step 4: First Startup

First, start it directly from the command line to confirm that everything is working properly, and then double-click the file to start it.

A lot of loading information will scroll through the window. Once it has quieted down and the server has started listening, open it with your browser:

You will see a chat page. Ask a random question, then try dragging a picture in to describe it. To stop the model, return to the PowerShell window and press Ctrl+C。

What do these parameters mean respectively:

parameter meaning
-m Path to the main model file
--mmproj The path of the multimodal component. You must use the one that matches the main model; you cannot mix it with other models.
-ngl 99 Put all the layers of the model into the graphics card as much as possible. It's not that the model has 99 layers.
-c 4096 The context length is the total amount that the model can "remember" in a single conversation. This is the runtime setting, not the upper limit of the model
-np 1 Only one request is processed at a time, saving resources.
--cache-type-k/v q8_0 Let the session cache use more memory-saving precision. It is different from the quantification of the model itself.
--image-min-tokens 1024 Minimum number of lexical elements used when processing images
--reasoning off Thinking is turned off by default. We'll explain later how to change it to allow switching on the webpage.
--host 127.0.0.1 Allows local access only, not to local area networks or the Internet
--port 8080 Ports used by web pages and interfaces

Possible problems

  • Insufficient memory, loading failure, or exceptional lagAfter loading the multimodal components with 8GB of graphics memory, there is less than 1GB left (my entire graphics card occupies 7364 MiB). First, close programs that occupy video memory, such as games, other AI software, and browsers with many tabs open. If that doesn't work, then... -c 4096 Smaller, or remove --mmproj $qwenMmproj This paragraph only contains text.
  • I only want to talk about words; I want a longer context.Remove --mmproj That part, put -c Change to 8192。 The 31.3 tokens/s I measured is this configuration, and the video memory usage is 6429 MiB. Text and multimodal use the same model; the only difference is whether or not visual components are loaded.
  • The webpage cannot be openedThe model will take some time to load. It will refresh after the loading information in the window stops. You can also run it in another PowerShell window Invoke-RestMethod 'http://127.0.0.1:8080/health' Check if the service is ready.
  • Prompt port is occupiedThis indicates that a program is already in use on the 8080, and it's very likely that the one you started earlier hasn't been closed yet. put --port 8080 Change to another number, for example 8089The website address was also changed accordingly.
  • Do not open two copies at the same time.The two model services use different ports and are also competing for memory from the same graphics card; 8GB is simply not enough.
  • "Multimodal" refers to pictures and videos。 In my configuration, the audio option in the interface is unavailable.

Precautions when reading

Step 3: Change the webpage interface to Chinese

The b10909's web interface is in English, and much of the text is hard-coded into the source code, with no readily available "language" option to switch between. My approach is to translate at the source code level and then rebuild it, using the same process as fixing the thinking menu above.

Specifically, I wrote a script that uses the Svelte compiler and TypeScript syntax analysis to read the source code, replaces the text on the interface with a Chinese-English bilingual dictionary, and then manually adds dynamic text that the script cannot handle (such as spelled-out sentences like "maximum 2,048 vocabulary"). The translation scope includes chat pages, sidebars, settings pages, think menus, tools menus, build progress, and statistics.

There are hundreds of entries in the dictionary, but I won't post them here. I'll just share a few useful tips for those who want to do it themselves:

  • Translate only the interface text; do not modify the strings used within the program. Like thinking hierarchy off、mediumThe tool's function names and interface parameter names are agreed upon between programs, and translation will cause errors. I mistakenly translated an internal prefix string halfway through, and only discovered it during checking and changed it back.
  • You can't just rely on "search for English and then replace". Even if you use grammatical analysis, you still have to look at the semantics one by one.
  • Back up before translating. I keep a repaired English version of the thinking menu, which I can switch back to at any time.
  • After the revisions are completed, inspections and tests are required. All 674 unit tests included in the project passed after translation; After that, I added a few more words and redid the checking, building, and browser verification.
  • The model's answers, your input, and the results returned by the tool will not be translated; only the interface will be translated into Chinese.

The final result is that chat, settings, thinking patterns, tool menus, and generation progress are all in Chinese, while the model and startup parameters remain completely unchanged.

At the end

Looking back, this didn't require particularly powerful hardware or knowledge of deep learning. There are three areas where time is really spent: trading off between "fast" and "comprehensive" when choosing a model, getting stuck on the encoding problem of a batch file, and figuring out whether the "think switch is missing" is a problem with the model, the server, or the webpage. Explain these three points clearly, and the rest is just to type the commands in order.

A few reminders:

  • The speed and memory figures in this article are records of my machine at the time; they will be different with different computers and power modes.
  • The model's benchmark score comes from Qwen official website and measures a model with complete accuracy; I'm running the quantified version locally; there are no retests.
  • Local models can also make serious mistakes, and you have to verify important information yourself.
